# 普联软件「Java 开发（财务信息化）」匹配度分析

_分析日期：2026-11-19。JD 原文来自智联招聘，已上市企业 300996，济南历城。_

## 一、JD 硬条件逐条对照

| JD 原文 | 你的情况 | 判定 |
|---|---|---|
| 计算机相关专业**本科及以上** | 计算机科学与技术，本科 | ✅ 符合 |
| **2027 年毕业的在校学生** | 2026-11 大三上 → **2028 届** | ❌ **不符，这是唯一的硬拦** |
| 掌握 Java 核心语法 | 90/100 天计划 D1–D28 覆盖 | ✅ 可达成 |
| 熟悉 Spring Boot 等基础框架 | D29–D49 项目一覆盖 | ✅ 可达成 |
| 了解 MySQL 数据库操作 | D15–D28 覆盖 | ✅ 可达成 |
| 有财务系统开发经验者**优先** | 无 | ⚠️ 加分项，不是门槛 |
| 实习 6 个月、5 天/周 | 大三下可协调 | ⚠️ 需确认 |
| 四六级 | **JD 全文未提** | ✅ 不影响 |

## 二、结论：卡你的不是四六级，是毕业年份

- **四六级**：这条 JD 一个字没提。普联虽有日本大阪机构，但财务信息化是国内业务线，实习技术面不会问英语。影响权重 <5%，可以完全忽略。
- **毕业年份**：JD 写的是「2027 年毕业的在校学生」，你是 2028 届。HR 筛简历第一层就是看这个字段，写了 2027 届的岗位会直接把 2028 届过滤掉。

## 三、概率估算

| 场景 | 拿到面试 | 拿到 offer |
|---|---|---|
| 现在（2026-11）投这条 2027 届岗，100 天学完 | 10%–15% | 5%–8% |
| 同上，但简历注明「2028 届、可连续实习 12 个月」争取放宽 | 20%–25% | 10%–12% |
| 2027-03 起（普联开 2028 届暑期实习通道）投，技术达标 | 50%–60% | 30%–40% |
| 2027-09 秋招正式批投 | 60%–70% | 30%–35%（竞争更激烈） |

技术准备度不是瓶颈：100 天计划走完，Java + Spring Boot + MySQL 三项正好覆盖 JD 全部技术要求。瓶颈是届数。

## 四、100 天要交付的东西（对齐普联 JD）

| 天数 | 内容 | 对应 JD 要求 |
|---|---|---|
| D1–D28 | Java 语法 → 面向对象 → 集合 → IO → 多线程 + MySQL 建表/索引/事务 | Java 核心语法、MySQL 操作 |
| D29–D49 | Spring Boot + MyBatis-Plus + Redis + JWT，做出 8 接口的完整后端 | Spring Boot 基础框架 |
| D50–D70 | 给项目加**财务/账务场景**：记账凭证表、科目余额、月度报表接口 | 「财务系统经验优先」这一条 |
| D71–D90 | 部署上线 + Swagger 文档 + 简历 + 八股一轮 | 面试通过率 |
| D91–D100 | 投递 + 面试复盘 + 补漏 | — |

**关键动作在 D50–D70**：把项目一改造成「简易记账/报销系统」。普联做的是石油石化、建筑、银行保险的管理信息化，财务场景一写进 README，就从「又一个 CRUD 学生项目」变成「和岗位方向对得上的项目」。这一步比多刷 20 道算法题有用得多。

## 五、现在就能做的两件事

**1. 照投，但在简历和招呼语里主动说明届数**

BOSS/智联的招呼语这样写：

```
您好，我是 2028 届计算机科学与技术本科生。看到岗位写 2027 届，
我情况特殊：大三下学期课少，2027-01 起可连续实习到 2027-08（7 个月），
之后可继续远程/每周 2-3 天至毕业，实际可投入时长比多数 2027 届更长。
已完成后端项目：Spring Boot + MyBatis-Plus + MySQL，含记账凭证与科目余额模块，
GitHub：<你的仓库链接>。方便的话想争取一次技术面机会。
```

这段话的作用：把「届数不符」变成「届数不符但我能待更久」，让对方有理由破例。实习岗的届数要求通常是「优先」不是「必须」，HR 有时会转发给技术负责人看。

**2. 把 2027-03 当成真正的投递点**

普联每年 3 月前后开暑期实习提前批，那时它是按 2028 届招的。你现在投是「争取破例」，那时投是「正常排队」。
